# Tool Selection, Routing, and Efficiency Techniques in Clinical/Medical LLM Agents

## How do clinical LLM agents retrieve/select relevant medical tools or knowledge sources when many are available? Any medical-domain-specific tool retrieval/routing papers (vs. general-domain)?

### Takeaway
Yes — several medical-specific papers propose two-stage "retrieve-then-select" or "metatool/nested-calling" architectures for choosing among large pools of clinical calculators, EHR functions, or guideline sources, distinct from general-purpose tool-retrieval work (e.g., ToolLLM-style retrievers); the general pattern is a cheap embedding-based first-pass filter over a large tool catalog followed by LLM reasoning to pick/parameterize the final tool.

### Cited Findings
- **AgentMD** curates 2,164 clinical calculators ("RiskCalcs") with executable functions and structured documentation, and "automatically select[s] and apply[ies] the relevant RiskCalcs tools given any patient description" at inference time; on the RiskQA benchmark it reaches 87.7% accuracy vs. 40.9% for chain-of-thought GPT-4 — [AgentMD (arXiv:2402.13225)](https://arxiv.org/pdf/2402.13225). A web-search summary (not independently verified against full text, since the PDF could not be parsed as text) describes the mechanism as "a two-step tool selection approach using first-stage retrieval by MedCPT and second-stage selection by LLMs," where first-stage retrieval returns the top-10 most relevant calculators from the full pool before an LLM commits to one — [search summary citing AgentMD](https://arxiv.org/pdf/2402.13225).
- **MeNTi** ("Bridging Medical Calculator and LLM Agent with Nested Tool Calling") proposes a "metatool and nested calling mechanism to provide more operations and information for solving practical tasks" for medical calculator selection — [MeNTi (arXiv:2410.13610)](https://arxiv.org/pdf/2410.13610). (Full-text could not be parsed via WebFetch — PDF returned as binary; mechanism description is from search-result summary only, not verified against the paper body.)
- **MedCalc-Pro**, "Solving Complex Medical Calculations with LLM Agents," is a related 2026 system for calculator-tool use — [MedCalc-Pro (arXiv:2607.02879)](https://arxiv.org/pdf/2607.02879) (not fetched in full; title/topic only).
- **EHR-MCP** evaluates LLM agents retrieving real-world clinical data via the Model Context Protocol, with agents decomposing clinical queries into discrete structured tool invocations (fetching specific labs, medications, diagnoses, etc.) rather than accessing raw records directly — [EHR-MCP (arXiv:2509.15957)](https://arxiv.org/pdf/2509.15957).
- **MedAgentBench** provides a FHIR-compliant, realistic virtual EHR environment (300 clinically-derived tasks, 10 categories, 100 patient profiles, 700,000+ data elements) for benchmarking how agents route among EHR tool calls (FHIR GET/POST for labs, orders, referrals, appointments); the best model evaluated (Claude 3.5 Sonnet v2) achieves a 69.67% task success rate, with "significant variation in performance across task categories" — [MedAgentBench (arXiv:2501.14654)](https://arxiv.org/abs/2501.14654).
- **PhysicianBench** similarly has agents interact with a FHIR-compliant EHR via structured tool calls (queries, medication orders, diagnostic service requests, referrals, appointments, patient communications) and evaluates against clinically grounded checkpoints — [PhysicianBench (arXiv:2605.02240)](https://arxiv.org/pdf/2605.02240).
- **EHRAgent** equips an LLM with a code-generation interface so it autonomously writes and executes code for multi-tabular reasoning over EHRs, framed as a few-shot alternative to enumerable tool-call APIs — [EHRAgent (arXiv:2401.07128)](https://arxiv.org/abs/2401.07128).
- For guideline/literature retrieval specifically: a multi-agent RAG system bridges clinical narratives to **ACR Appropriateness Criteria** for medical imaging decisions — [Bridging Clinical Narratives and ACR Appropriateness Guidelines (arXiv:2510.04969)](https://arxiv.org/pdf/2510.04969); "ClinicBot" is a guideline-grounded clinical chatbot using "Prioritized Evidence RAG" with verifiable citations — [ClinicBot (arXiv:2605.00846)](https://arxiv.org/pdf/2605.00846). A described general pattern (from search-result synthesis, not a single verified primary source) is "routing-then-retrieval," mapping queries to guideline sections before evidence assembly, and multi-agent orchestrators using "clinical query-type routing and authority-weighted reranking" to rank guideline content by clinical evidence grade before narrative text — [search synthesis](https://www.maargasystems.com/2025/06/06/exploring-agentic-rag-in-healthcare/).
- **MedAgent** (evidence-based medicine agent) extracts PICO elements from a clinical question, invokes evidence-retrieval tools, and receives multi-level medical evidence for grounding — [MedAgent (medRxiv 2026.06.15.26355735)](https://www.medrxiv.org/content/10.64898/2026.06.15.26355735v1.full).

### Inferences
- The dominant medical-domain pattern (AgentMD, MeNTi) mirrors general-domain tool-retrieval approaches (embedding-based pre-filtering + LLM final selection, akin to ToolLLM/Gorilla-style retrievers) but is specialized around curated clinical-calculator or FHIR-resource catalogs rather than generic API catalogs — this is the clearest "medical-specific tool retrieval" angle for a workshop paper to contrast against general-domain tool retrieval.
- EHR tool-use benchmarks (MedAgentBench, PhysicianBench) suggest routing/selection among EHR tools remains a harder, less-saturated problem than calculator selection — success rates under 70% even for frontier models — implying tool-selection accuracy itself (not just efficiency) is still a bottleneck in this domain, unlike many general-domain tool-use benchmarks that are closer to saturated.

### Gaps
- Could not verify the AgentMD two-stage MedCPT retrieval mechanism or MeNTi's nested-calling details against primary full text (WebFetch returned binary/undecodable PDF content for both); these mechanism descriptions come from search-engine-generated summaries and should be treated as secondary/unverified pending direct full-text confirmation.
- No direct, explicit paper found comparing medical-domain tool retrieval methods head-to-head against general-domain tool-retrieval baselines (e.g., ToolBench's retriever) on a shared metric — this remains a gap for positioning the "specialization" claim.

## What efficiency techniques (caching, reducing redundant calls, cost-aware planning for expensive diagnostic tools) have been studied in medical agent systems?

### Takeaway
Cost-aware planning for sequential test/imaging ordering is an active, well-formalized research line (GraphDx, CDPR, EvoClinician) that explicitly models dollar cost and invasiveness as penalties in tool-selection utility functions, going beyond general-agent "API call cost" framing; separately, EHR-querying agents (EHR-MCP) report concrete caching gains against redundant data-fetch calls, though this is less studied than the diagnostic cost-planning literature.

### Cited Findings
- **GraphDx** ("A Cost-Aware Knowledge-Enhanced Multi-Agent Framework for Sequential Diagnosis," arXiv:2607.15280) builds LLM-constructed Medical Diagnosis Knowledge Graphs with cost-sensitivity attributes and uses three agents (Perception, Reasoning, Decision); its Reasoning Agent computes a utility score per candidate test, U(τ) = Σ V(f)·η(f,τ) / (1 + c_τ·ι_τ), balancing discriminative information gain against financial cost (c_τ) and invasiveness (ι_τ) — [GraphDx](https://arxiv.org/html/2607.15280).
- On MedQA (DeepSeek-V3 backbone), GraphDx improves diagnostic success from 67.8% to 88.7% while cutting average test cost from $1,062.69 to $537.13 (a 49% reduction); on real-world MIMIC-IV data it improves a diagnostic score from 6.60 to 8.27 while cutting cost from $737.43 to $340.98 (54% reduction) — [GraphDx](https://arxiv.org/html/2607.15280).
- GraphDx explicitly names the failure mode it targets: LLMs exhibit a "knowledge-reasoning gap" leading to "defensive medicine" — ordering excessive tests to compensate for reasoning uncertainty while failing to use discriminative features for efficient differential diagnosis — [GraphDx](https://arxiv.org/html/2607.15280) (via search synthesis of the paper's framing).
- A baseline multi-agent system, MAI-DxO, is reported to cost $2,460 average on MedQA (vs. GraphDx's much lower cost), to collapse to a diagnostic score of 5.38 on a smaller Llama-3.3 backbone (model-size dependency), and to generalize poorly to MIMIC-IV ($1,497 cost, lower accuracy) — [GraphDx](https://arxiv.org/html/2607.15280).
- **CDPR** ("Counterfactual Advantage-based Credit Assignment for Cost-Aware Sequential Medical Diagnosis," arXiv:2608.28599) is a reinforcement-learning-style credit-assignment method purpose-built for cost-aware sequential diagnosis — title/topic confirmed via search listing; full mechanism not independently fetched — [CDPR](https://arxiv.org/pdf/2608.28599).
- **EvoClinician** ("A Self-Evolving Agent for Multi-Turn Medical Diagnosis via Test-Time Evolutionary Learning," arXiv:2601.22964) incorporates both a "base per-turn interaction cost" and "test-specific costs for ordered tests," reported in normalized units, directly building cost into its agent-loop reward — [EvoClinician](https://arxiv.org/pdf/2601.22964) (via search summary).
- **MIRA**, an autonomous medical AI agent evaluated on 574 real-world ED cases from MIMIC-IV across 8 diagnoses using 11 specialized digital tools (over 85,000 operational tool-use choices), achieved 88.9% diagnostic accuracy overall and 87.8% in a matched 311-case comparison against physicians; it requested only about half of the lab analytes obtained in routine MIMIC-IV care (below-baseline utilization, not an "order-everything" strategy), and higher lab-test coverage "did not translate into systematic over-ordering of higher-cost imaging" — [Towards autonomous medical artificial intelligence agents, Nature (s41586-026-10675-5)](https://www.nature.com/articles/s41586-026-10675-5) (findings via search-result synthesis of the Nature paper; not independently fetched in full).
- **EHR-MCP** reports a direct tension: "more comprehensive tool usage improved answer correctness" but "introduced significant call redundancy" — LLMs frequently re-queried previously retrieved information, suggesting weak internal state-tracking across tool calls; caching strategies "substantially reduced unnecessary calls," improving both efficiency and (indirectly) performance metrics together — [EHR-MCP (arXiv:2509.15957)](https://arxiv.org/pdf/2509.15957).
- General-domain (non-medical) context on caching, for comparison: production agentic workloads show "heavy cross-request redundancy," and semantic/tool-result caching has been shown to cut LLM calls by as much as 41.6% in a three-agent pipeline — included here as general-agent baseline context, not a medical-domain finding — [Semantic Caching for AI Agents](https://www.logicmonitor.com/blog/semantic-caching-what-we-measured-why-it-matters).

### Inferences
- Medical agent efficiency research has bifurcated into two distinct efficiency concerns that general-agent tool-use papers typically collapse into one: (1) computational/API efficiency (redundant tool calls, caching — e.g., EHR-MCP), and (2) real-world clinical-action cost efficiency (dollars, invasiveness, risk of an ordered test — e.g., GraphDx, CDPR, EvoClinician, MIRA). A workshop paper extending general tool-use-optimization surveys into healthcare should treat these as two separate axes, since the dominant and most mathematically formalized medical-specific contribution (cost-in-the-utility-function diagnostic planning) has no direct general-domain analogue beyond abstract "monetary API cost" framings.
- The GraphDx vs. MAI-DxO comparison is the clearest available "more tool calls / more agents != better" cautionary data point quantifying cost blowup from naive multi-agent diagnostic approaches, useful as a concrete number for a survey's efficiency section.

### Gaps
- Could not fetch CDPR, EvoClinician, or MIRA (Nature) full text directly (relied on search-engine summaries); numbers reported should be flagged as secondary-sourced pending direct verification against the primary PDFs/HTML.
- No paper found that benchmarks *caching hit rates* or exact % reduction in duplicate EHR/lab calls with a specific number (EHR-MCP's summary mentions caching qualitatively but no verified quantitative cache-hit-rate statistic was retrievable from the parse).

## Are there published cost/latency considerations unique to healthcare tool-use (unnecessary lab/imaging order vs. unnecessary general API call)?

### Takeaway
Yes — this distinction is explicit and quantified in the clinical-agent literature (GraphDx, MIRA, CDPR, EvoClinician all build real-world dollar/invasiveness cost directly into the agent's decision objective), and is grounded in a well-documented real-world baseline: human "defensive medicine" over-testing is estimated at $46–60 billion/year in the US, with up to 25% of imaging ordered inappropriately (~$30 billion), giving medical LLM agent researchers a concrete non-computational cost benchmark that general-domain agent efficiency papers do not have.

### Cited Findings
- Defensive medicine (physician over-ordering to limit liability, independent of LLMs) is estimated to add $46–60 billion annually to US healthcare spending; orthopedic surgeons reported ordering 19.1% of imaging tests and 38.5% of MRIs for defensive reasons; more broadly, up to 25% of imaging tests are ordered inappropriately or defensively, at an estimated cost of $30+ billion — [Reducing the Cost of Defensive Medicine, Center for American Progress](https://www.americanprogress.org/article/reducing-the-cost-of-defensive-medicine/); [Exploring defensive medicine, PMC](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC10563204/).
- GraphDx frames this directly as the risk LLM clinical agents inherit: a "knowledge-reasoning gap" causing LLMs to default to the same "defensive medicine" over-testing pattern as human clinicians, motivating explicit cost/invasiveness penalties in its tool-utility function rather than treating all tool calls as equal-cost — [GraphDx (arXiv:2607.15280)](https://arxiv.org/html/2607.15280).
- EvoClinician's cost model explicitly separates a cheap "base per-turn interaction cost" from distinct, higher "test-specific costs for ordered tests," formalizing that not all tool calls in a clinical agent cost the same (unlike typical general-agent treatments where every API call is often weighted equally or purely by token/latency cost) — [EvoClinician (arXiv:2601.22964)](https://arxiv.org/pdf/2601.22964) (via search summary; not independently verified in full text).
- MIRA's evaluation explicitly separates "lab test coverage" cost from "higher-cost imaging" cost and reports that the agent did not let higher lab utilization bleed into imaging over-ordering — an empirical demonstration that a clinical-specific agent can be evaluated on a cost hierarchy (cheap labs vs. expensive imaging) that has no direct equivalent in general API-cost accounting — [Towards autonomous medical artificial intelligence agents, Nature](https://www.nature.com/articles/s41586-026-10675-5) (search-summary sourced).
- GraphDx's utility formula explicitly includes an invasiveness term (ι_τ) alongside a monetary cost term (c_τ), i.e., a dimension (physical/psychological harm or risk from the test itself, e.g., biopsy vs. blood draw) with no analogue in general-domain "API call cost" framings — [GraphDx (arXiv:2607.15280)](https://arxiv.org/html/2607.15280).

### Inferences
- The clearest unique-to-healthcare framing a workshop paper can make: general-agent tool-use efficiency research treats "cost" as (near-)uniform compute/latency/dollar-per-API-call, whereas medical agent research must model a *heterogeneous* cost space — monetary cost, physical invasiveness/risk, and clinician time — that differs by orders of magnitude between tool types (a blood draw vs. an MRI vs. a biopsy), and the real-world human baseline (defensive medicine, $46–60B/yr) gives this literature an externally-validated reference point that general-domain efficiency papers lack (there is no equivalent "humans also over-call APIs for $60B/year" baseline in software agent research).

### Gaps
- No paper found directly computing a formal "cost of an unnecessary clinical tool call" in the same units as (and explicitly contrasted against) "cost of an unnecessary general-agent API call" — the comparison above is an inference drawn from juxtaposing separate literatures (defensive-medicine economics research + clinical-agent cost-aware planning papers), not a single primary source making that comparison itself.
- Did not find quantified latency considerations (e.g., turnaround time cost of ordering a lab test that takes hours/days vs. an instant API call) explicitly modeled in any clinical agent paper — this seems to be an underexplored angle (most papers model dollar cost and invasiveness, not wait-time/throughput latency), worth flagging as a gap/opportunity for the workshop paper.

## What role does human-in-the-loop / clinician oversight play as an "efficiency" lever, and is it framed as analogous to general-agent cost-aware stopping research?

### Takeaway
Yes — there is a directly on-point paper ("Safe to Stop?") that formalizes clinical-agent escalation/deferral explicitly as a *risk-constrained optimal-stopping* problem (naming it this way), which is the clearest available bridge concept between general-agent "early-stopping"/cost-aware-stopping research and medical human-in-the-loop oversight; separately, staged-autonomy and confidence-calibration frameworks propose escalation thresholds as a resource-allocation (not just safety) mechanism.

### Cited Findings
- **"Safe to Stop? Risk-Constrained Stopping for Sequential Clinical Diagnosis Agents"** (arXiv:2609.09678, GenAI4Health 2026) explicitly frames the clinical question as: an agent must decide not only what test to request next but "when to diagnose or defer," since "stopping too early can miss a consequential disease" while "stopping too late wastes tests and may expose patients to avoidable procedures" — [Safe to Stop?](https://arxiv.org/html/2609.09678).
- Its method, **CROS** (Clinical Risk-constrained Optimal Stopping), explicitly optimizes to "minimize resource cost subject to two population constraints: conditional diagnostic error among autonomous decisions is at most α, and autonomous coverage is at least γ" — i.e., human escalation (non-autonomous coverage) is treated as a tunable budget constraint traded off against resource (test) cost, directly analogous to cost-aware/early-stopping formulations in general sequential-decision agent research — [Safe to Stop?](https://arxiv.org/html/2609.09678).
- On a 1,834-episode MIMIC-derived abdominal-pain benchmark, CROS achieves 16.9% selective diagnostic error at 78.8% autonomous coverage using 0.68 tests on average, versus 30.8% error at 100% coverage using 1.53 tests under "native" (non-risk-constrained) stopping — i.e., deferring ~21% of cases to a human roughly halves both the error rate and the number of tests needed per case — [Safe to Stop?](https://arxiv.org/html/2609.09678).
- **"From Black-Box Confidence to Measurable Trust in Clinical AI: A Framework for Evidence, Supervision, and Staged Autonomy"** (Zabolotnii, Holinko, Antonenko; arXiv:2604.26671, April 2026) proposes that clinical AI should progress through discrete "staged autonomy" levels based on demonstrated trustworthiness rather than a binary human/AI split, implicitly framing deferral-threshold tuning as a way to balance "excessive clinician burden" against "unsafe autonomous operation" — a cost-aware framing, though the paper does not explicitly cross-reference general-purpose agent early-stopping literature (per the accessible summary) — [From Black-Box Confidence to Measurable Trust (arXiv:2604.26671)](https://arxiv.org/pdf/2604.26671) (note: summarized via automated extraction since the PDF could not be parsed as clean text; treat mechanism specifics as secondary/unverified).
- In the AgentClinic benchmark, agent "doctor" stated confidence is reported as meaningfully calibrated — "higher reported probabilities on the reference diagnosis are associated with higher empirical accuracy" — which the authors frame as grounds for hope that "future models may recognize when to act autonomously and when to defer to human judgment" — [search synthesis citing AgentClinic](https://www.nature.com/articles/s41746-026-02674-7).
- A related framing describes uncertainty quantification acting "as a gatekeeper, flagging highly accumulated uncertainty moments to invite humans, automating during low-uncertainty periods" — [Uncertainty Quantification in LLM Agents (arXiv:2602.05073)](https://arxiv.org/pdf/2602.05073) (via search synthesis; general UQ-for-agents paper, not medical-specific — included because it is explicitly cited/adjacent in medical-agent escalation search results, but flagged as possibly general-domain in scope).
- "Modeling Clinical Concern Trajectories in Language Model Agents" (arXiv:2604.27872) proposes "a lightweight agent architecture [that] integrates a memoryless clinical risk encoder over time using first- and second-order dynamics to produce a continuous escalation pressure signal," yielding "smooth, anticipatory concern trajectories" — [Modeling Clinical Concern Trajectories](https://arxiv.org/pdf/2604.27872) (title/abstract-level only; full text could not be parsed via WebFetch, PDF returned as binary — treat specifics as unverified pending direct access).

### Inferences
- "Safe to Stop?" is the strongest available citation for the survey's thesis that medical human-in-the-loop escalation is a direct, formally-stated analogue of general-agent cost-aware/early-stopping research — it uses optimal-stopping language explicitly and ties the stopping decision to the same two levers (accuracy/error budget, resource/test cost) that general-agent cost-aware-stopping papers use, just substituting "defer to human" for "terminate the agent loop."
- The CROS numbers (0.68 vs. 1.53 average tests, 78.8% vs. 100% coverage) give a concrete, citable "escalate ~1 in 5 cases, cut tests in half, roughly halve error" data point that a workshop paper can use as its headline example of human oversight functioning as an efficiency lever in medicine.

### Gaps
- Could not verify "Modeling Clinical Concern Trajectories" or the staged-autonomy paper's full mechanisms/results beyond what automated PDF-to-text summarization returned; both PDFs failed to parse as clean text via WebFetch, so quotes attributed to them should be treated as secondary (search/extraction-tool-generated) rather than directly confirmed against original text.
- No paper found that explicitly and directly cites/compares itself against general-agent early-stopping or cost-aware-stopping literature by name (e.g., citing bandit-based or MDP-based agent stopping-rule papers from the general LLM-agent-efficiency literature) — "Safe to Stop?" uses the same conceptual vocabulary (optimal stopping, resource cost, coverage/error tradeoff) but an explicit cross-domain citation link was not found/verified.

## Are there direct comparisons of accuracy vs. number of tool calls/retrieval steps in clinical QA or diagnostic agent tasks — does more retrieval/tool-use always improve accuracy, or are diminishing/negative returns documented?

### Takeaway
Yes, directly — AgentClinic provides an explicit, quantified non-monotonic relationship between the number of agent-patient interaction turns and diagnostic accuracy (an inverted-U shape), and GraphDx/MAI-DxO comparisons separately show that more agents/more tool calls does not monotonically improve diagnostic cost-efficiency; a related general-domain tool-calling paper documents the same diminishing-returns pattern for tool-call count vs. utility.

### Cited Findings
- In **AgentClinic**, reducing the number of patient-interaction turns from N=20 to N=10 "significantly decreases accuracy from 52 to 25%," attributed to insufficient information gathering; conversely, increasing N beyond 20 to N=30 "slightly reduces accuracy," attributed to the complexity of processing larger inputs — i.e., "doctor agents excel in a specific range of conversation turns, [and] more or less interactions reduces their diagnostic accuracy," an explicit inverted-U / non-monotonic finding — [AgentClinic (arXiv:2405.07960 / Nature s41746-026-02674-7)](https://www.nature.com/articles/s41746-026-02674-7) (via search synthesis of the paper; recommend verifying exact figures against the primary PDF before citing in final report, as this was not independently confirmed via direct fetch).
- AgentClinic also reports a tool-use ablation: across six "agent tools" (Zero-Shot CoT, One-Shot CoT, Reflection CoT, Adaptive RAG-Book, Adaptive RAG-Web, Notebook), Claude 3.5 achieved its highest average accuracy of 51.3% overall, peaking at 56.1% specifically when using the Notebook tool — i.e., different tool choices (not just more tools) produce materially different accuracy, and the best-performing "tool" was not necessarily a retrieval/RAG tool — [AgentClinic](https://www.nature.com/articles/s41746-026-02674-7).
- AgentClinic additionally reports "a tradeoff between reasoning cost and performance for each model, measured by accuracy versus average tokens per scenario," on the AgentClinic-MedQA variant — a direct accuracy-vs-compute-cost curve — [AgentClinic](https://www.nature.com/articles/s41746-026-02674-7).
- GraphDx vs. MAI-DxO (described above) shows that a multi-agent framework without cost-aware planning (MAI-DxO) spends far more (average $2,460 on MedQA) without matching GraphDx's accuracy, and its accuracy "collapses" on a smaller backbone — evidence that more agents/tool invocations do not reliably buy more accuracy and can simply inflate cost — [GraphDx (arXiv:2607.15280)](https://arxiv.org/html/2607.15280).
- In the general-domain (non-medical) tool-calling literature, for comparison: "true utility gain plateaus as the number of tool calls increases, reflecting diminishing returns," and an optimized tool-calling strategy ("Probe&Prefill") reduces tool calls by 48% with only 1.7% accuracy loss, while the best accuracy-matched baseline only achieves a 6% call reduction — included as general-domain context, confirming the diminishing-returns pattern is not medical-specific but the medical literature independently documents its own version — [To Call or Not to Call (arXiv:2605.00737)](https://arxiv.org/html/2605.00737v1).
- EHR-MCP (above) documents a related but distinct phenomenon: more tool calls can even become *counterproductive* through redundancy (re-querying the same data) rather than just plateauing, because of weak agent state-tracking — [EHR-MCP (arXiv:2509.15957)](https://arxiv.org/pdf/2509.15957).

### Inferences
- The AgentClinic N=10/20/30 finding is the single best direct, quantified citation available for the key question "does more retrieval/tool-use always improve diagnostic accuracy" — it demonstrates an explicit inverted-U, not just a monotonic plateau, which is a stronger and more citable claim than the general-domain "diminishing returns" framing (which typically shows a plateau, not an actual decline).
- Taken together with GraphDx/MAI-DxO, there appear to be (at least) two distinct documented failure modes for "more tool-use" in clinical agents: (1) accuracy degradation from context/complexity overload past an optimal interaction count (AgentClinic), and (2) cost inflation without accuracy gain from naive multi-agent/more-testing strategies (GraphDx vs. MAI-DxO). A workshop paper could present these as two separate sub-claims under "diminishing/negative returns in medical tool-use."

### Gaps
- The AgentClinic N=10/20/30 statistics and the Claude 3.5 Notebook-tool 56.1% figure were obtained via search-engine summarization of the paper rather than a confirmed direct read of the primary PDF/HTML (WebFetch was not used on this specific paper due to tool-budget constraints) — recommend the report-writer flag this as needing a verification pass against the primary source (arXiv:2405.07960 or Nature s41746-026-02674-7) before treating exact percentages as final.
- No paper was found that systematically varies *retrieval steps specifically* (as opposed to conversational/interaction turns) and reports a clean accuracy curve for medical RAG-over-guidelines systems specifically (e.g., "accuracy vs. number of guideline chunks retrieved") — the AgentClinic finding is about interaction turns with a simulated patient, which is related but not identical to "retrieval steps" in a RAG sense; this is a gap if the workshop paper wants a RAG-chunk-count-specific curve.
