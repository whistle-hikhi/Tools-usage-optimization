# General-Purpose Biomedical "AI Scientist" Tool Suites

## What large, general-purpose tool catalogs exist for biomedical/medical LLM agents (ToolUniverse's direct peers)?

### Takeaway
ToolUniverse (Harvard) and Biomni (Stanford) are the two dominant general-purpose biomedical tool catalogs: both mine large tool/database/API pools from the literature and wrap them behind a retrieval-plus-LLM-selection agent, rather than hand-curating a small fixed toolset. Both are catalogs an agent is *built from*, distinct from the benchmark/evaluation harnesses (MedAgentBench, AgentClinic, etc.) already covered in the companion medical tool-use report.

### Cited Findings
- **ToolUniverse** ([GitHub: mims-harvard/tooluniverse](https://github.com/mims-harvard/tooluniverse); [docs](https://zitniklab.hms.harvard.edu/ToolUniverse/guide/skills_showcase.html); [launch post](https://zitniklab.hms.harvard.edu/2025/06/03/ToolUniverse)) — built by Shanghua Gao, Marinka Zitnik and colleagues at Harvard Medical School. Advertises 600+/1000+ scientific tools spanning ML models, databases, APIs, datasets, and scientific packages, plus dozens of prebuilt "agent skills" for complex research tasks (binder discovery, bioinformatics resource discovery, biomedical fact lookup, cancer classification, clinical-trial-design feasibility assessment, multi-omics layer-by-layer analysis). A more recent framing cites 211+ biological/medical tools integrated via the **Model Context Protocol (MCP)**. Its "AI-Tool Interaction Protocol" is explicitly designed to give a common interface across GPT, Claude, Gemini, and open-source models.
- ToolUniverse powers **[TxAgent](https://zitniklab.hms.harvard.edu/TxAgent/)** — "An AI Agent for Therapeutic Reasoning Across a Universe of Tools" — which evaluates drug interactions at molecular, pharmacokinetic, and clinical levels, retrieves/synthesizes evidence from multiple biomedical sources, and selects tools based on task objective to execute structured function calls for therapeutic tasks.
- **Biomni** ([GitHub: snap-stanford/biomni](https://github.com/snap-stanford/biomni); [paper PDF](https://biomni.stanford.edu/paper.pdf); [PMC12157518](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12157518/)) — Stanford SNAP Lab's general-purpose biomedical agent. Uses an "action discovery agent" to mine essential tools, databases, and protocols from literature, analyzing ~2,500 biomedical research papers across 25 subfields to construct a unified agentic environment. The resulting **Biomni-E1 environment** ships 150 specialized biomedical tools, 105 software packages, and 59 databases. Its agent architecture (**Biomni-A1**) combines LLM reasoning with retrieval-augmented planning and code-based execution: given a query, it first retrieves the most relevant tools/databases/software, then plans a step-by-step workflow. Biomni also maintains a "Know-How Library" — curated best-practice protocols and troubleshooting guides automatically retrieved when relevant.
- **BioMedArena** ([arXiv:2605.06177](https://arxiv.org/pdf/2605.06177)) — an open-source toolkit specifically for building and evaluating biomedical *deep research* agents (literature-synthesis-oriented rather than clinical-action- or tool-execution-oriented); adjacent category, not a direct ToolUniverse/Biomni peer.

### Inferences
- ToolUniverse and Biomni both solve the same underlying problem (how does an agent choose among hundreds of biomedical tools) with the same architectural primitive already identified as dominant in the general-domain companion report: cheap retrieval narrows a large pool, then LLM reasoning makes the final selection/execution — i.e., the retrieve-then-select pattern is not clinical-benchmark-specific (AgentMD, MeNTi) but also the backbone of the largest general biomedical tool catalogs.
- Neither ToolUniverse nor Biomni is cited by the clinical-benchmark papers already summarized in the companion report (MedAgentBench, FHIR-AgentBench, AgentClinic, AgentMD, MeNTi, EHR-MCP) — these sit at a different layer (tool catalog / agent substrate vs. evaluation harness), and no paper located in this pass runs one of these clinical benchmarks *using* ToolUniverse or Biomni as the tool backend. This is a candidate gap: does a frontier agent's FHIR-AgentBench or MedAgentBench score change if it draws on a 1000-tool catalog like ToolUniverse rather than the benchmark's own ~9 built-in FHIR tools?

### Gaps
- Tool counts for ToolUniverse vary across sources (211 vs. 600+ vs. 1000+) depending on which release/documentation page is cited — the discrepancy was not resolved in this pass and should be checked against the current GitHub README before citing a specific number in a paper draft.
- No controlled comparison found between ToolUniverse-backed and Biomni-backed agents on a shared benchmark.
